# 功能需求初稿

## 1. 系统定位

本系统是一个面向租户客户公司的 Web SaaS。
客户通过扫码枪扫描条码/二维码，系统根据扫码结果找到对应邮箱并发送邮件。
系统支持多租户，并允许每个租户维护自己的用户、订阅、办公室/学校、扫码编号与邮箱对应关系。

---

## 2. 一级功能模块

### 2.1 租户功能管理

租户管理员登录系统后，可以进入租户功能管理页面，管理本租户的基础数据和功能模块。

包含以下子模块：

- 维护用户账号订阅
- 新增或删除办公室/学校
- 维护扫码编号与邮箱对应关系（人员一览）
- 扫码邮件（核心功能）
- 群发邮件

### 3.3 扫码邮件（核心功能）

扫码邮件是 MVP 的核心功能。

#### 3.3.1 前置条件

- 用户已登录系统
- 用户已选择办公室/校舍
- 当前租户订阅状态为有效
- 扫码编号与邮箱对应关系已维护

#### 3.3.2 订阅限制

当租户订阅状态为：

- 有效：允许扫码和发送邮件
- 过期/暂停：限制扫码和邮件发送功能

#### 3.3.3 页面显示

进入扫码邮件页面后，系统显示：

- 办公室/校舍切换
- 扫码输入区域
- 邮件文本编辑区域
- 最近扫码/邮件发送结果
- 当前订阅状态提示

#### 3.3.4 邮件正文规则

邮件正文由两部分组成：

```text
固定前缀 + 用户自定义文本

#### 3.3.5 扫码流程
1. 用户进入扫码邮件页面
2. 用户切换办公室/校舍
3. 系统检查当前租户订阅状态
4. 若订阅有效，显示扫码面板和邮件文本编辑区域
5. 用户使用扫码枪扫描条码/二维码
6. 系统接收扫描结果
7. 系统根据扫描结果查找对应邮箱

#### 3.3.6 找到对应邮箱时
1. 创建扫码记录
2. 创建邮件发送任务
3. 邮件文本固定显示：
   - 租户公司名
   - 办公室/学校名
4. 后续扩展：允许用户自定义邮件文本
5. 系统向对应邮箱发送邮件
6. 记录邮件发送结果
7. 管理员可以查看历史记录并导出

#### 3.3.7 未找到对应邮箱时
1. 系统提示“未找到对应邮箱”
2. 记录异常扫码事件
3. 管理员后续确认并补充人员信息

## 4. 当前已确定的业务规则

### 4.1 多租户
- 每个客户公司是一个租户
- 每个租户有独立的数据范围
- 用户只能访问所属租户的数据

### 4.2 办公室/学校维度
- 一个租户可以有多个办公室/学校
- 扫码邮件操作前，需要先切换当前办公室/校舍
- 邮件内容中需要体现办公室/学校名

### 4.3 邮件文本
MVP 阶段：
- 邮件文本固定显示租户公司名和办公室/学校名
- 后续版本支持用户自定义邮件文本

### 4.4 异常处理
- 若扫码结果找不到对应邮箱，不发送邮件
- 需要记录异常扫码事件
- 管理员需要能够后续确认和修正人员信息
