- A、B、C 均经无头浏览器使用合成 operator、active 订阅和已分配地点正常提交。逐笔按响应中的扫码和任务 ID 匹配历史与 SQL。源冻结后为 **A、B**，还原后为 **A**。切换后重新登录，B 在目标历史中缺失；新提交 C 后，目标为 **A、C**，只读源仍为 **A、B**。B 与 C 均为离场扫码，拥有不同 ID。两端最终各有 2 笔任务、2 笔成功 mock 尝试。业务损失按独立扫码计数，相关任务、投递、登录及审计行可随同变化。
