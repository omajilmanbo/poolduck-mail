# A05 值守续期与断网恢复

## 单标签页在线值守

2026-11-20（日本时间），固定候选 `a05251897d7fc11d96114606bcaa1807dd96af55`。一个合成操作员在单标签页通过正常 UI 登录。浏览器原生 Cookie 时钟和候选后端的应用时钟使用相同偏移，浏览器单调计时、PostgreSQL 时钟与宿主时钟维持实时时间。[矩阵 A05](business-requirements-matrix.md#A05) · [值守需求记录](https://github.com/omajilmanbo/poolduck-mail/issues/80#issuecomment-5043792596)

| 检查 | 实测结果 |
| --- | --- |
| 值守时长 | 受控 24 小时 17 分 10 秒，实际约 70 秒。 |
| 读取与续期 | 登录 1 次，历史读取最终成功 293 次。其中 197 次直接返回 200，另 96 次在历史请求 401 后续期 201、重新读取 200。登录后的续期失败为 0，真实数据库审计同样记录 1 次登录和 96 次成功续期。 |
| 工作台 | 地点、状态筛选和未提交的扫码草稿持续保留，登录表单未重新出现。 |
| 业务写入 | 扫码、邮件任务、投递尝试各为 0。 |

登录前的一次匿名刷新 401 单独计数。实测覆盖单标签页在线值守和 access Cookie 到期后的恢复。

## 双设备值守与短时断网恢复

同日使用相同正式候选。同一合成操作员在两个独立的无头 Chromium 上下文通过正常界面登录，模拟两台设备，受控登录时间相差 4 分钟。设备 A 在约 122 秒的受控离线期间达到 access Cookie 到期点。离线点击历史「刷新」只收到浏览器网络错误。恢复联网后，空历史页面静置 9.413 秒，期间没有发出 API 或续期请求。设备 B 在 A 离线和恢复观察期间共 11 次直接读取历史成功。

| 检查 | 实测结果 |
| --- | --- |
| A 恢复联网后点击「刷新」 | 历史请求 401 → 自动续期 201 → 原历史读取 200。网络错误提示消失，页面及地点、筛选、未提交草稿均保留。 |
| B 到达自己的 access 到期点后点击「刷新」 | 同样经历 401 → 201 → 200。B 保留自己的筛选和未提交草稿，A 继续直接读取历史成功。 |
| 会话与业务写入 | 同一用户有两条有效会话，两端各登录一次、续期一次，全程无需重登。数据库只观察到认证相关写入，业务写请求、业务表的写入增量及扫码、任务、投递尝试均为 0。 |

恢复联网后静置的结果限于本次空历史页面和观察窗口。两设备同时续期、旧刷新值重放及 refresh Cookie 到达 7 天期限仍待验证。[候选的历史轮询条件](https://github.com/omajilmanbo/poolduck-mail/blob/a05251897d7fc11d96114606bcaa1807dd96af55/frontend/app/page.tsx#L72-L81)
