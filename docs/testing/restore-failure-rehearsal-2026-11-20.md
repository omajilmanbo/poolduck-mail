# 损坏归档的中止与恢复验收

2026-11-20（日本时间）。三套独立的本机 PostgreSQL 16.16 使用固定候选 `a052518` 的迁移与合成数据，应用和队列处理关闭。核对归档完整性、故障后目标库状态和完整原件恢复后的业务关联。[矩阵 O08](business-requirements-matrix.md#O08) · [恢复策略 #38](https://github.com/omajilmanbo/poolduck-mail/issues/38)

| 场景 | 实测结果 |
| --- | --- |
| 独立清单校验 | 使用完整归档生成可信 SHA-256 清单。测试副本截短 512 字节后，使用原清单校验返回 1。流程在调用还原前停止，目标仍为 0 张业务表。 |
| 单独验证损坏副本 | `pg_restore --list` 返回 0。完整单事务还原遇到 EOF 并返回 1，回滚后目标仍为 0 张业务表。 |
| 使用完整原件 | 第三个全新实例校验和还原均成功。21 项迁移完成，19 张表的行数及内容摘要与源库演练前后相同。 |

只读查询核对了租户、地点、人员、扫码及任务关系。原有 1 笔已到期 `waiting` 任务仍未认领，尝试数和调用标记均为 0。该次恢复验收到只读数据库客户端接入为止。异地取回、密钥恢复及生产规模的恢复耗时仍待验证。
