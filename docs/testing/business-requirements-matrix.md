一行对应一个可单独验收的行为。**实现位置**链接到源码或明确标记缺失。**已核证据**用 B、F、DB、E 标出此 SHA 的 CI 断言。独立补验、历史报告与静态核对另有标记。**历史**带日期或来源，**静态**表示只核对代码／配置，**待定**表示仍缺决定。最后一列列出差异和可关闭它的验证，未列冲突的行按所引现行规则验收。优先顺序只用于安排补证，不构成发布批准。

更换候选时先固定 SHA 和 main run，逐个核对 checkout、job 日志、执行命令和测试断言，再更新受影响行。沿用行号，新增要求另起行。碰到改义或延期，保留旧来源和取代它的决定。Issue 状态以 GitHub 为准，提出日期、测试通过、合并与环境启用分别记录。保留聚合结果即可。

日常记录清理在新 PostgreSQL 16 库应用候选的 21 项迁移后，以模拟 Production 配置启动候选调度组件。三类对象在 1／10／100 三档均达到每类上限，8 次只读计数与 SQL 核对一致，冻结和在途记录保留。组件停用后观察 61.002 秒，无清理执行。[RET08 灰度报告](candidate-record-retention-rollout-2026-11-20.md)

另一次隔离验收在完整候选 Backend 内运行真实分钟调度。两个租户冻结时，三组合成样本共 18 条原行全部保留；正式恢复接口返回 201 后，下一轮只清除恢复租户已到期的一组。新生成的恢复审计、清理结果审计均仍存在。两条审计各自的一年到期点由只读 SQL 推算。[恢复与下一轮清理](candidate-record-retention-rollout-2026-11-20.md#restore-next-run)

一条合成扫码在真实时钟下经历首次 sandbox 失败和三次重试，从上次完成到下次认领分别为 30.019、120.107、600.561 秒。最终为 `failed`，重启后仍只有四次调用。工作台每 2 秒轮询当前页，最多 10 轮。超过窗口后，操作员普通刷新可看到同一记录的“发送失败”和安全错误提示。[M03 耗尽报告](candidate-mail-retry-exhaustion-2026-11-20.md)

扫码幂等与去重专项通过 14 项检查。两个同地点获权的 operator 通过独立 HTTP 连接并发提交，另在本租户其他地点及另一租户核对写入隔离。最终 SQL 对账为 4 条扫码、4 个邮件任务、3 次 sandbox 投递尝试及 5 条幂等记录，取消任务零尝试。10 秒和 24 小时各自的前 1 ms、恰好到期和后 1 ms 由候选服务在独立的 PostgreSQL 事务中以固定时钟核验。[扫码幂等与去重补验](candidate-scan-dedup-2026-11-19.md)。

同一候选另做两项本机验收。等待任务写入失败后，独立数据库连接确认扫码、等待任务、幂等记录和投递尝试均为 0。原键重试只创建一套记录，同地点同动作换人员返回 409，再次提交原请求仍回读原记录。[扫码事务与重放](candidate-s05-s06-scan-atomicity-2026-11-20.md)
