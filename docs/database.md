# Database design (initial draft)

> Note: Use English for field naming and Chinese for document descriptions.

## 1. tenants

> Usage: Tenant master table, representing an independent customer organization; used as the top boundary for multi-tenant data isolation and billing attribution.

- `id` (pk, uuid)
- `name` (varchar)
- `status` (varchar) - active/suspended
- `created_at` (timestamp)
- `updated_at` (timestamp)

## 2. users

> Usage: Can log in to the administrator account table of the system (only background management users, not equivalent to recipients). Administrators are divided into two categories: `root_admin` (can edit subscriptions, add or delete locations) and `manager` (can only maintain `person_mappings`).

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id)
- `email` (varchar, unique within tenant)
- `password_hash` (varchar)
- `role` (varchar) - root_admin/manager
- `status` (varchar)
- `last_login_at` (timestamp, nullable)
- `created_at` (timestamp)
- `updated_at` (timestamp)

## 3. subscriptions

> Usage: Subscribe to the configuration table (MVP subscribes to tenant first); managed by `root_admin`.

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id, unique)
- `plan` (varchar)
- `status` (varchar) - trial/active/expired/suspended
- `start_at` (timestamp)
- `end_at` (timestamp)
- `created_at` (timestamp)
- `updated_at` (timestamp)

## 4. devices

> Usage: QR code scanning device registry, recording terminal devices under the tenant that can report QR code scanning events.

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id)
- `device_code` (varchar)
- `name` (varchar)
- `status` (varchar)
- `last_seen_at` (timestamp, nullable)
- `created_at` (timestamp)
- `updated_at` (timestamp)

## 5. scan_events

> Usage: Scan code event flow table, save the original scan code input and receiving time, for tracing and subsequent email task association.

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id)
- `device_id` (fk -> devices.id, nullable)
- `scan_code` (varchar)
- `scan_type` (varchar) - barcode/qrcode
- `raw_payload` (text)
- `received_at` (timestamp)
- `created_by_user_id` (fk -> users.id, nullable)
- `created_at` (timestamp)

## 6. locations (office/school)

> Usage: office/school context table; the user needs to select the current location before scanning the QR code, and subsequent search and sending actions are completed within this context.

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id)
- `location_code` (varchar) - business-readable encoding, such as OFFICE_A / SCHOOL_1
- `name` (varchar) - Office/school name
- `type` (varchar) - office/school
- `status` (varchar) - active/inactive
- `created_at` (timestamp)
- `updated_at` (timestamp)

> Note: In order to satisfy "switch office/school building before scanning the QR code", `locations` is named as the only formal context within the tenant.

## 7. person_mappings (scan code number and person email mapping)

> Usage: Non-logged-in person (recipient) mapping table, maintaining `scan_code -> person_name/email` in location; maintained by `manager` and `root_admin`. Strictly distinguished from `users`: `users` is the login administrator, and `person_mappings` is the business address book mapping.

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id)
- `location_id` (fk -> locations.id)
- `scan_code` (varchar)
- `person_name` (varchar)
- `email` (varchar)
- `status` (varchar) - active/inactive
- `created_at` (timestamp)
- `updated_at` (timestamp)

> Query constraints: `scan_code` search must bring both `tenant_id` and the current `location_id` (office/school context). Global search only by `scan_code` is prohibited to avoid mismatching across tenants or across offices/schools.

## 8. mail_jobs

> Usage: Email sending task table, recording the delivery status and error information from generation to sending completion/failure. MVP only saves the final `subject`/`body` generated by the system, and does not save the user-defined body separately.

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id)
- `scan_event_id` (fk -> scan_events.id, nullable)
- `to_email` (varchar)
- `subject` (varchar)
- `body` (text)
- `template_key` (varchar)
- `status` (varchar) - queued/sent/failed
- `retry_count` (int)
- `provider_message_id` (varchar, nullable)
- `error_message` (text, nullable)
- `scheduled_at` (timestamp, nullable)
- `sent_at` (timestamp, nullable)
- `created_at` (timestamp)
- `updated_at` (timestamp)

## 9. audit_logs

> Usage: Audit log table, records key operations, resource objects and execution results of administrators to meet compliance and problem tracking.

- `id` (pk, uuid)
- `tenant_id` (fk -> tenants.id, nullable for system ops)
- `actor_user_id` (fk -> users.id, nullable)
- `action` (varchar)
- `resource_type` (varchar)
- `resource_id` (varchar)
- `result` (varchar) - success/fail/denied
- `metadata_json` (jsonb)
- `created_at` (timestamp)

## 10. Index suggestions

- `users (tenant_id, email)` unique
- `users (tenant_id, role, status)`
- `subscriptions (tenant_id)` unique
- `devices (tenant_id, device_code)` unique
- `scan_events (tenant_id, received_at)`
- `locations (tenant_id, location_code)` unique
- `locations (tenant_id, name)`
- `person_mappings (tenant_id, location_id, scan_code)` unique
- `person_mappings (tenant_id, location_id, status, updated_at)`
- `mail_jobs (tenant_id, status, created_at)`
- `audit_logs (tenant_id, created_at)`
