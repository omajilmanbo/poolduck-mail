# API Draft (MVP)

## Agreement

- Base path: `/api`
- Auth: `Authorization: Bearer <token>`
- All business interfaces are executed in the tenant context by default
- Tenant isolation: receive and verify `tenant_id` when logging in; after successful login, the business interface uses `tenant_id` in token/session, and does not accept `tenant_id` explicitly passed in by the business interface
- Unified subscription status: `trial` / `active` / `expired` / `suspended`
- The text of the scanned email is always generated by the backend and does not accept custom text fields such as `custom_message` / `custom_text` / `mail_body`
- Fixed email body template: `Notice from {tenant_name}, {location_name}: {person_name} completed the action at {time_stamp}. `

## 1. Authentication (Auth)

### POST `/api/auth/login`
- Input parameters: `tenant_id`, `email`, `password`
- Output parameters: `access_token`, `expires_in`, `user`
- Error: "tenant does not exist" is returned when `tenant_id` does not exist; login failure is returned when the user is not in the tenant or the password is incorrect.

### POST `/api/auth/logout`
- Description: Invalidate the current token/session

### GET `/api/auth/me`
- Description: Get the current logged in user information

## 2. License Check

### GET `/api/license/check`
- Description: Verify current tenant subscription availability
- Output parameters: `status`, `plan`, `expired_at`
- Permissions: logged in user (`root_admin` / `manager`)

## 3. Scan code email core process API

### GET `/api/locations`
- Description: Get the list of locations (offices/school buildings) available for the current tenant, which can be used to switch context by scanning the email page.
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirement: None (only for page initialization)
- Output parameters (example field): `[{ location_id, location_name, is_active }]`
- Error: Cross-tenant location not visible

### GET `/api/locations/{location_id}/people`
- Description: Get the list of people under the current location (office/school building) and the mapping of scan code numbers
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirement: None (only for map preloading)
- Output parameters (example fields): `[{ person_id, person_name, scan_code, email_masked }]`
- Error: A recognizable error is returned when `location_id` is illegal or does not belong to the current tenant

### POST `/api/scan-events`
- Input parameters: `location_id`, `scan_code`
- illustrate:
  - Create QR code scanning event records
  - The backend searches for the email address corresponding to the scanned code number in the current tenant + location context.
  - The backend generates the final email body according to a fixed template
  - Backend creates associated email tasks (initially `queued`)
  - Does not receive any custom body fields (`custom_message` / `custom_text` / `mail_body` etc.)
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirements: `trial` or `active`; `expired` / `suspended` returns invalid subscription error
- Output parameters (example fields): `scan_event_id`, `mail_job_id`, `mail_subject`, `status`
- Errors:
  - `location_id` is illegal or does not belong to the current tenant
  - `scan_code` does not find the mapped mailbox: returns an identifiable business error, and records the scan code event as an abnormal state (such as `unmapped`) for subsequent troubleshooting
  - Invalid subscription

### POST `/api/mail-jobs/{mail_job_id}/send`
- Description: Confirm/trigger sending the specified email task (default is used to send after scanning the QR code)
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirement: `trial` or `active`
- Output parameters (example fields): `mail_job_id`, `status`, `provider_result`
- Errors:
  - The email task does not belong to the current tenant
  - The task status does not allow sending (such as sent)
  - The provider fails to send (returns an identifiable error code and error message)

### GET `/api/mail-jobs/{mail_job_id}`
- Description: Query email sending results and failure reasons
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirements: None (historical results are available)
- Output parameters (example fields): `mail_job_id`, `status`, `sent_at`, `error_code`, `error_message`

### GET `/api/scan-events/{id}`
- Description: Query a single QR code scan record (including associated email task status)
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirements: None (history can be checked)
- Output parameters (example fields): `scan_event_id`, `person_id`, `person_name`, `time_stamp`, `status`, `mail_job_id`

### GET `/api/scan-events`
- Query: `location_id`, `status`, `created_from`, `created_to`
- Description: Query the QR code scanning record by location (office/school building) and status, which is used for display in the "QR code scanning record column" on the page.
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirements: None (history can be checked)
- Output parameters (example fields): `[{ scan_event_id, person_id, person_name, time_stamp, status }]`

## 4. Compatible with reserved interfaces (non-QR code scanning main process)

### POST `/api/mail-jobs`
- Description: Manually create email tasks (subject to permission control), used for non-code scanning paths or background operation and maintenance
- Permissions: Administrator (`root_admin`)
- Subscription requirement: `trial` or `active`

### GET `/api/mail-jobs`
- Query: `status`, `created_from`, `created_to`
- Permissions: logged in user (`root_admin` / `manager`)
- Subscription requirements: None

### POST `/api/mail-jobs/{id}/retry`
- Description: Retry failed email tasks
- Permissions: Administrator (`root_admin`)
- Subscription requirement: `trial` or `active` (`expired` / `suspended` prohibited)

## 5. Admin Tenants (Administrator)

### GET `/api/admin/tenants`
- Description: Query tenant list (Platform Administrator)
- Permissions: platform administrator (`root_admin`)

### GET `/api/admin/tenants/{id}`
- Description: Query tenant details
- Permissions: platform administrator (`root_admin`)

### PATCH `/api/admin/tenants/{id}/status`
- Description: Update tenant status (`trial` / `active` / `expired` / `suspended`)
- Permissions: platform administrator (`root_admin`)
