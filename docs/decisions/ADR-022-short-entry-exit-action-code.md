# ADR-022：人员动作码改用 E/X 单字符前缀

- 状态：Accepted
- 日期：2026-10-16
- 相关 Issue：#150

## Context

ADR-015 已接受并实现 `V2E<person_code>` / `V2X<person_code>`。业务负责人现要求去除 `V2`，直接用 `E` 表示入室、`X` 表示退出。扫码码由后端解析、前端生成 QR/Code 128 图片，也出现在 API 示例、测试和合成容量工具中；各处格式不一致会造成扫码失败或错误动作。Staging 已存在测试地点和生成的人员动作码，切换前需明确旧图片的处置。

## Decision

将人员动作码固定为 13 位大写 ASCII 字母数字：入室 `E<12 位 person_code>`，退出 `X<12 位 person_code>`；严格语法为 `^[EX][0-9A-HJKMNP-TV-Z]{12}$`。首字符是动作，不再有版本字段。`person_code` 的生成、不可变性、tenant/location 授权、订阅门禁、10 秒去重、幂等、取消、历史和邮件目标规则均不变。

在同一应用版本中同步切换后端解析器、前端四张 QR/Code 128 资产、输入提示、合成 seed/smoke/load/E2E 和现行文档。不双读：旧 `V2E` / `V2X`、`PD1`、裸 `person_code` 和畸形输入均返回 `ACTION_CODE_INVALID`，不创建扫码事件或邮件任务。服务端不猜测或修正扫码枪输入；仅保留现行单个 Enter/CR/LF 后缀规则。

本决定 supersede ADR-015 的负载语法、版本字段和资产编码；ADR-015 其余扫码枪兼容原则、ADR-008 双动作语义和 ADR-002/003/018 安全边界继续有效。

## Alternatives considered

1. 保留 `V2E` / `V2X`：无需重印，但不满足本次简化要求。
2. 同时接受 13 位新码和 15 位旧码：可缓冲已发放资产，但增加长期双格式误用、测试和运维成本；若已有不可重印的正式资产，应在接受本 ADR 前改选此方案并明确终止日期。
3. 只使用裸 `person_code`、由页面推断进入/退出：违背 ADR-008 的显式动作来源，不采用。

## Consequences

- 正面：码缩短两位；扫码枪只需输入一个动作前缀及人员码。
- 负面：旧图片和手工记录的 `V2` 码在切换后失效；没有版本字段，未来格式升级须通过长度/语法与新的迁移决策识别。

## Migration impact

- 不修改数据库 schema、人员业务码、历史扫码事件或既有邮件任务，不回填历史载荷。
- 发布前盘点并重新下载/打印所有仍会使用的 Staging 动作码；新解析器与新图片必须同步交付。若已有不能同步更换的正式资产，停止实施并重新决策兼容方案。
- 切换前完成合成测试和 mock smoke；回滚应用版本时必须同时回滚/撤回新版图片，避免新旧不匹配。不以重新发送历史邮件作为回滚方式。

## Security impact

- 动作码是公开定位符而非凭据。服务端仍只在已认证 tenant、已授权 location 内查 active 人员，不能按公开码全局查询。
- 旧码、畸形码、无权地点、无效订阅和无映射人员不得创建可发送任务；错误响应不得泄露其他 tenant/location 是否存在该人员。
- 日志、指标和 Issue 不记录真实完整动作码、人员邮箱、姓名或跨 tenant 映射。

## Operational impact

- 发布前检查前后端版本一致、四资产往返解码、手工/扫码枪输入、mock 路径与回滚办法。真实邮件测试仍需独立批准。
- 用户指南、管理员指南与扫码错误提示需明确旧 `V2` 码失效，并指导重新取得新码。

## Follow-up

- 2026-10-16 人工批准：旧 `V2` 码直接失效，现有图片同步重新生成或重印；据此实施 #150。
- #150 同步更新 `docs/architecture.md`、`docs/api.md`、`docs/requirements.md`、`docs/user-guide.md`、`docs/admin-guide.md`、`docs/testing.md` 和受影响的合成工具及测试。
