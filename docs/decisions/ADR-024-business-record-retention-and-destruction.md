# ADR-024：基本数据墓碑与记录型业务数据的一年保留和销毁

- 状态：Accepted
- 日期：2026-10-22
- 相关 Issue：#170, #171, #172, #173, #174, #175, #176

## Context

现行 ADR-008、ADR-011 与 ADR-023 要求保留扫码、邮件和审计历史，Production 租户终结清理后仍留下可能包含姓名、邮箱、邮件正文或上下文快照的记录。2026-10-22 用户决定区分两类数据：租户、租户管理员/操作员及客户基本数据属于持续服务所需的当前对象，删除后留下最小非 PII 关系墓碑；扫码、邮件、回执和审计属于有时效性的记录，到期完全销毁。用户不采用“在线一年、再归档两年”的默认方案。

ADR-023 已规定 Production 租户从删除请求起按日历年保留一年并可恢复。日常记录若在这段窗口内继续按原到期时间销毁，会使删除期间的数据无法按删除时状态恢复；若一律再延长两年，又缺少已确认的查询用途。`scan_events`、`mail_jobs`、`mail_delivery_attempts`、扫码幂等记录之间有外键，不能分别无序删除。Production 备份生命周期尚未设计，不能把在线数据库行的销毁描述为备份副本也已消失。

本 ADR 记录用户于 2026-10-22 接受的业务规则和随后明确的恢复处理：恢复后立即按正常期限清理超期记录，不设额外导出宽限期。接受本决策不代表清理 worker 已部署或已对现有数据执行销毁。

## Decision

1. **两类数据。** `tenants`、`users`（包括 `tenant_manager` / `operator`）、`locations`、`person_mappings`、`devices` 等当前基本对象，在服务期间按现有状态与权限规则保存。对象到达其已批准的终结清理点后，清除姓名、邮箱、用户名、密码哈希、当前名称等 PII，仅保留维持不可复用业务码、内部关系和状态所需的非 PII 墓碑。ADR-011 的人员/地点 14 天恢复期，以及 ADR-023 的 Production 租户一个日历年恢复期，保持不变；Staging 租户立即清理保持不变。墓碑不能用于重新登录、扫码或发信。
2. **记录型数据与正常期限。** Production 的 `scan_events`、关联 `mail_jobs`、`mail_delivery_attempts`、发送时上下文/邮件内容快照、租户 `audit_logs` 和 `platform_audit_logs` 采用一个日历年的正常保留期。扫码与邮件作为一个记录家族，以根 `scan_events.created_at` 的数据库时间加 `interval '1 year'` 计算到期；邮件任务与发送尝试随家族一同销毁，不能留下失联子行。租户与平台审计各以本行 `created_at + interval '1 year'` 到期。闰日、UTC 时间边界与数据库时钟为权威，不能用固定 365 天替代日历年。到期后的目标是物理销毁在线业务数据库中的完整记录与关联 PII，不保留内容墓碑或可逆归档副本。
3. **有效发送与安全边界。** 只有记录家族内邮件任务已进入终态、没有正在执行的 provider 调用且其关联行可完整事务删除时，日常清理器才可销毁该家族。未终态、状态未知但仍可能有在途调用、外键关系不完整或事务失败时跳过并报警，不能靠改变发送状态、自动重发或强制删除来满足时限。`delivery_unknown` 是终态证据，不应被改写；到期销毁前必须确认没有仍在途的调用。清理按外键子表到父表顺序、小批次、幂等事务执行；清理失败回滚本批。审计历史在期限内不得因清理设计被改写成另一种业务事实。
4. **Production 租户删除窗口。** 租户进入 ADR-023 的 `pending_delete` 后，冻结该租户当时尚存的记录型数据日常到期销毁，直到 `purge_after`。删除期间不因此恢复新扫码或发信权限。若在截止前恢复，立即解除冻结；已经超过正常一年期限的记录立即重新成为清理候选，不提供额外导出宽限期，也不承诺恢复后继续显示超期历史。若截止前未恢复，终结清理在同一受控流程中销毁该租户在线业务数据库的扫码、邮件、回执、幂等和租户业务审计记录，再清理当前对象 PII 并保留基本数据墓碑；不等待记录自身满一年。对于因租户暂停而仍为 `waiting` / `queued` 的任务，先确认发送门禁持续阻断且没有在途 provider 调用，再随租户记录销毁；不可为清理而调用 provider 或伪造 `sent`。删除与恢复仍由数据库时间、租户行锁和事务协调，失败不得宣称清理完成。平台操作审计按独立的一年期限处理，并可保留新的、仅含安全内部 ID 与计数的清理结果行。
5. **不建设两年归档。** 本期没有对象存储历史归档、归档查询接口或两年额外期限。租户可在正常期限内使用已有权限查询/导出记录；到期后不能通过产品界面查询已销毁内容。日后如有明确的更长追溯或法定义务，应另立决策，说明记录类型、用途、权限和期限，不以“归档”自动延长保存。
6. **权限与平台审计。** `tenant_manager` 仍只查询本租户业务审计；`operator` 的现有地点范围历史查询不扩大。`platform_admin` 可以通过独立的只读页面和 API 查询 `platform_audit_logs`，按时间、操作、结果、平台管理员和目标租户筛选、分页；响应仅包含安全白名单字段。尚未完成的租户删除流程相关平台审计可延至流程完成，以免失败补偿失去追踪依据；流程结束后按原始 `created_at` 判定，已超期即进入清理候选。平台管理员不因此获得租户 `audit_logs`、扫码、邮件、人员或正文读取权限。平台审计页和 API 分别由 #174、#175 实施。
7. **其他数据边界。** Session、幂等键、运行时日志、OCI Email Delivery 日志与数据库备份不因本 ADR 自动继承一年期限；各自已有的较短有效期或运维策略继续适用。扫码幂等行必须在其关联记录家族销毁前清理。ADR-023 对 Production 备份副本不作承诺、对 Staging 不设保留期的边界保持不变；在备份生命周期另行决定和实施前，不能对外宣称所有副本已完全销毁。

本 ADR 局部取代 ADR-008、ADR-011、ADR-013 和 ADR-023 中“扫码、邮件、回执、上下文快照和审计历史永不删除或在终结清理后继续保留”的规定。其余关于原始事实不可伪造、邮件状态安全、当前对象墓碑、角色隔离、删除权限和恢复窗口的决定继续有效。`docs/admin-guide.md` 当前“Production 审计日志保留 90 天”与本决策不一致，实施 Issue 必须同步修正；在清理功能上线前，不能把一年到期销毁写成现状。

## Alternatives considered

1. 在线一年后再归档两年：没有已确认的两年查询用途，仍持续持有可能包含 PII 的记录，暂不采用。
2. 历史永久不可变且永不删除：与本次明确的有时效性记录完全销毁目标冲突，不再作为 Production 到期策略。
3. 租户待删除期间仍按日常到期销毁：无法保证一年恢复窗口内保留删除时仍存在的记录，不采用。
4. 恢复后另给超期记录导出宽限期：用户明确选择立即恢复正常期限，不采用。
5. 到期只匿名化历史快照：不能满足记录完全销毁，也可能留下可重新关联的行为轨迹，不采用。

## Consequences

Production 的记录型业务数据不再无限增长，也不需要建设没有明确用途的两年归档。删除中的租户可能使部分记录短暂超过自身正常一年期限，最迟在租户恢复或到期终结清理后重新进入销毁流程。恢复后超期历史可能很快消失，产品说明需清晰告知。过期历史不能再用于事后查询、争议处理或重建投递链路；需要更长期限时必须重新作业务决定。

## Migration impact

先以默认关闭的开关、索引、FK 清理矩阵和合成数据验收准备功能。既有 Production 历史不得因部署迁移立即无核对地批量删除；先盘点按 tenant、记录类型和月份的到期行数，确认清理顺序、容量和回滚/停用路径，再分批启用。#162/#163 已有的 Production 租户终结清理目前保留历史，须由 #173 改为本 ADR 的销毁语义。Staging 已有的整租户立即清理路径不改。

需要同步更新 `docs/product.md`、`docs/architecture.md`、`docs/database.md`、`docs/api.md`、`docs/admin-guide.md`、`docs/deployment.md`、`docs/observability.md` 和 `docs/issue-archive.md`。新页面与 API 上线时再更新用户可见说明。所有文档应区分“已接受的目标规则”和“已部署的实际清理能力”。

## Security impact

清理与审计查询都必须显式绑定服务端身份和 tenant 范围；平台审计使用独立平台 guard，不能复用允许可空 `tenant_id` 的租户查询。清理日志、指标和平台操作结果只记录安全内部 ID、计数和原因码，不复制邮件正文、邮箱或原始扫码载荷。租户墓碑不得通过历史 API 复活。对未知租户、已清理记录、无权限地点与非法游标使用一致的安全错误语义，不能通过是否已归档或销毁泄露其他租户存在性。

## Operational impact

Production 清理器默认关闭，发布需人工审核。每批记录候选、成功、跳过、失败和最老逾期时间的聚合指标与告警；未终态邮件、在途 provider 调用、FK 冲突、积压或结果不一致时停止相关批次并告警。终结清理与日常清理必须可重试且不能产生邮件发送。备份副本及恢复演练的保留/清除仍由独立决策处理；本 ADR 只定义在线业务数据库的销毁。
