# 用户操作手册（初版）

网页手册 `/help` 使用 `frontend/src/help/content.json` 作为共用摘要；修改摘要后运行 `npm --prefix frontend run help:sync`，一致性由前端测试检查。以下详细说明继续作为补充。

## 网页手册共用内容

这里说明租户操作员和租户管理员在扫码工作台中的常用操作。无需登录即可阅读；手册不显示任何租户数据。

### 登录

- 输入管理员提供的 10 位 tenant_code、用户名或邮箱，以及密码。operator 可用用户名或已绑定邮箱；tenant_manager 使用邮箱。
- 首次使用一次性临时密码的租户管理员需要先修改密码，再重新登录。登录失败时检查输入，仍无法进入请联系租户管理员。

### 选择地点与扫码

- 先选择当前地点。operator 只能看到租户管理员已分配的地点；没有地点时请联系租户管理员。
- 进入时扫描 E<person_code>，离开时扫描 X<person_code>。旧 V2 动作码已失效，需要重新下载或打印。
- 扫码成功后有 10 秒取消窗口。只有页面显示可取消的等待任务时才能点击“取消发送”；最终以服务端结果为准。取消成功会阻止该邮件并使本次误扫动作失效，原始记录仍保留；确认取消后可重新扫描正确动作。

### 查看扫码记录

- 工作台只显示当前地点有权查看的扫码记录；刷新可重新读取当前列表，等待中的任务会短时更新状态。
- 记录保留原始进入或离开动作。已取消的误扫会标为已取消；页面倒计时不会延长服务端取消期限。

### 邮件任务状态

- 可取消等待中（waiting）：还在 10 秒窗口内；仅按钮可用时可以申请取消。
- 发送中（queued）：任务等待自动重试；发送中（processing）：系统正在处理发送。
- 已发送（sent）：mock 模式表示模拟发送成功；OCI 模式仅表示邮件服务已接受提交，不代表邮件已到达收件箱。
- 发送失败（failed）：本次任务已失败；已取消（canceled）：本次任务不会发送。
- 投递结果未知（delivery_unknown）：系统无法确认邮件服务是否接受，既不能认定已送达，也不能认定发送失败；请联系管理员核查，不要据此直接重复扫码。

### 人员与动作码

- 在“人员管理”查看有权限地点的人员。人员邮箱在列表中脱敏显示。
- 点击“查看动作码”可在浏览器中查看进入和离开的二维码与 Code 128 条形码；可分别下载图片或下载 ZIP，打印时确认动作标识。

### 角色与管理入口

- operator 可在已分配地点管理人员并扫码，不具有用户管理、地点管理或审计管理入口。
- tenant_manager 可使用“人员管理”“用户管理”“地点管理”和租户“审计”入口，并为 operator 配置地点权限。平台管理员功能不属于租户工作台。
- 订阅为 expired 或 suspended 时不能新建扫码与发送任务；已有权限内的历史仍可查看。

### 常见问题

- 看不到地点：请租户管理员检查地点是否启用，以及 operator 的地点分配。
- 提示动作码无效：确认使用完整的大写 E 或 X 动作码，不要使用旧 V2 图片、裸人员码或额外前后缀。
- 误扫后想撤回：在等待窗口内点击“取消发送”；若按钮已不可用，不能把已开始的发送当作可撤回。
- 邮件未到收件箱：先查看任务状态；即使显示“已发送”，也可能仍需管理员核查邮件服务的后续投递结果。

## 1. 登录

1. 打开系统登录页
2. 输入管理员提供的 10 位 `tenant_code`；不再输入 UUID
3. 输入“用户名/邮箱”与密码：operator 可使用用户名或已绑定邮箱，tenant_manager 必须使用邮箱
4. 登录成功后进入扫码工作台
5. 登录后使用 HttpOnly Cookie 保持会话：access token 有效期 15 分钟，refresh token 有效期 7 天并在刷新时轮换
6. 工作台会在 access token 过期时静默刷新，因此正常值守不会因 15 分钟 access token 到期而被直接退出；退出登录会撤销当前设备会话

## 2. 扫码录入

1. 连接扫码枪
2. 选择当前 location。operator 只会看到 tenant_manager 已显式分配的地点；未分配任何地点时列表为空，需要联系 tenant_manager 授权
3. 根据实际动作扫描该人员的两张动作码之一：进入码为 `E<person_code>`，离开码为 `X<person_code>`；两张码仍只能在已登录的正确 tenant 与 location 中使用。旧 `V2` 图片已失效，需重新下载或打印
4. 系统显示识别结果与提交反馈（不支持自定义邮件正文预览）
5. 提交后系统会在事务内创建扫码记录和 `waiting` 邮件任务；10 秒内可点击“取消发送”，未取消则由 worker 到期领取并按环境配置交给 mock 或 OCI 邮件服务。页面显示“可取消等待中”“已取消”“已发送”“发送中（等待重试）”“发送失败”或“投递结果未知”
6. 发送失败会依次在 30 秒、2 分钟、10 分钟后自动重试，三次重试耗尽后终止；页面不提供人工发送按钮
7. 当订阅状态为 `expired` 或 `suspended` 时，系统应禁用扫码提交、邮件创建、发送与重试入口；`trial` 与 `active` 可继续使用
8. 人员映射列表仅显示脱敏邮箱，完整邮箱不在扫码页面只读接口中展示
9. 当动作码没有当前 tenant/location 的 active 映射邮箱时，系统提示“未找到对应邮箱”，不创建扫码记录、处理工单或邮件任务
10. 最近扫码记录显示“进入”“离开”或旧数据的“动作未知”；邮件正文与该记录使用同一动作
    新邮件通知的主题包含租户、地点和「入室/退室」；正文列出人员姓名、动作及日本时间。已创建的历史邮件任务和重试仍使用当时固化的文本。
11. 10 秒内重复扫描同一人员的同一动作码会返回首次结果；若在该窗口内扫描相反动作码，系统提示动作冲突且不新增记录或邮件

> 成功扫码后，记录状态右侧会显示最长 10 秒的“取消发送”按钮。取消成功同时阻止邮件并使误扫动作
> 不再参与当前进出状态，原始记录仍显示“已取消”；取消后可立即重新扫描正确动作。倒计时按服务端
> 时间校正；网络失败或 409 时页面不会宣称已取消，而会刷新服务端权威状态。
> 页面休眠、设备时钟快慢、刷新或重新登录都不会延长窗口；小窗口下状态与取消按钮保持分开可读。

> 扫码枪兼容性说明：动作码只使用大写字母数字，不含分隔符。扫码枪国家键盘配置仍应与 Windows 活动布局匹配，并只配置无后缀或一个 Enter/CR/LF 后缀；系统不按厂牌/型号建立白名单，也不会猜测修复错误布局产生的字符。

## 3. 查看邮件任务

- 工作台会从后端恢复当前 location 的最近扫码记录，刷新浏览器后记录不会丢失。
- 扫码记录已按当前 location 筛选，列表首列显示人员名称而不重复显示地点，便于人工核对；历史数据无法取得人员名称时显示 `-`。
- 记录显示 `waiting` / `queued` / `processing` / `sent` / `failed` / `canceled` / `delivery_unknown` 对应状态；非终态会有限轮询，达到终态或轮询上限后停止。
- “已发送”在 mock 模式下是模拟发送成功，在 OCI 模式下仅表示服务商接受提交，不等于收件箱已送达；“投递结果未知”既不能认定成功，也不能认定失败，不能据此直接重复扫码。
- “刷新”按钮可手动重新加载当前 location；网络失败和登录失效会显示明确提示。
- 页面时间按浏览器当前时区显示；后端和导出统一使用 UTC 时间。
- `operator` 只能在已授权 location 的“人员管理”中新增人员并维护姓名、邮箱和启停状态；`tenant_manager` 可管理本 tenant 全部地点。人员 ID/扫描码由系统生成且不可编辑，也不允许把人员映射移动到其他地点。
- 人员列表的“查看动作码”会在浏览器内生成进入/离开的二维码与 Code 128 条形码共四张 PNG。每张图片可单独下载，也可打包为一个 ZIP；图片只包含 `E<person_code>` 或 `X<person_code>` 和明显的动作标识，不包含姓名、邮箱、tenant/location UUID，且不会上传到外部图片服务或保存到服务器。
- 人员 ID 缺失或格式无效时，动作码预览会显示错误并禁用下载，不会回退使用内部 UUID。
- `tenant_manager` 可使用“用户管理”“地点管理”和“审计”入口；“用户管理”仅维护本 tenant 的
  `operator`，创建时 username 必填、邮箱可选，并可修改登录身份、启停和重置密码。修改身份、停用或
  重置都会撤销该 operator 的现有会话。
- “用户管理”的“地点权限”列会显示 operator 当前可操作地点。tenant_manager 可点击“配置地点”多选启用地点；地点较多时可在选择列表内滚动，小窗口下取消和保存按钮仍保持可见。撤销前需确认影响，保存后新权限立即生效。已停用地点不可新增分配。
- `operator` 不显示“用户管理”入口，也不能直接访问该管理功能。
- 平台管理员的“平台审计”页面只列平台操作，提供时间、管理员、动作、结果与目标租户筛选及分页；租户“审计”仍只显示本租户业务操作。普通租户账号不能打开平台审计页面。
- 地点管理只需输入地点名称，地点 ID 由系统生成；页面不要求手工代码或 office/school 类型。
- 停用地点后禁止新扫描和映射写入，排队邮件会安全终止；既有记录在正常保留期限内仍可查询。tenant_manager 可在地点管理重新启用。
- 人员和地点均提供独立“删除”。确认后进入 14 天恢复期，操作区会在删除状态右侧显示“恢复”和剩余
  天数；恢复会还原删除前的启用/停用状态。到期后系统自动清理当前个人信息；扫码和邮件记录按 Production 正常一年期限另行销毁，清理器启用前仍按现有查询能力显示。
- 停用人员后，人员 ID 保留，既有历史在正常保留期限内可查询；可在人员管理重新启用，前提是所属地点已启用。
- tenant_manager 撤销 location assignment 后，operator 的新扫码、人员写入和历史请求会立即停止；重新授权后才恢复。
- ADR-018 已移除“未映射扫码”页面。未找到映射的输入不会保存到扫码历史，也不能通过创建或复用相同人员 ID 来“修正”；系统不会自动补发邮件。

## 4. 常见问题

- 登录失败：系统不会区分 tenant_code、账号、停用或密码错误；检查输入后仍失败时联系 tenant_manager
  重置 operator 密码。tenant_manager 恢复使用受控平台流程
- 登录时提示“无法连接后端 API”：确认后端服务已启动，前端 API 地址正确，并由管理员检查 CORS 白名单
- 扫码无响应：检查设备输入焦点与连接
- Code 128 解码正常但输入字符错误：先停止业务提交，使用合成动作码在本地文本输入框记录逐字符输出，并由管理员核对 USB HID 键盘国家/布局、Windows 当前键盘布局和前后缀设置；不要用猜测字符替换 `|`
- 提示“动作码无效”：确认扫描的是完整且区分大小写的 `E<person_code>` 或 `X<person_code>`；`V2` / `PD1` 旧码、裸人员码、前后空格、设备前缀或重复 Enter 后缀都不能提交
- 提示“动作冲突”：等待 10 秒后确认实际动作再重扫；系统不会按每日次数、零点或上一条记录自动猜测动作
- 邮件未送达：先查看任务状态并联系管理员；即使显示“已发送”，也可能需要进一步核查服务商的后续投递结果
由平台管理员新开通的首个 `tenant_manager` 使用一次性临时密码首次登录。登录成功后系统会立即
跳转到 `/change-password`；完成至少 8 位且同时包含英文字母和数字的新密码前，其他租户业务
接口返回 `PASSWORD_CHANGE_REQUIRED`。改密成功会清除当前会话，必须使用新密码重新登录。
普通既有用户不会被 migration 自动标记为首次改密。
