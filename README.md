# Poolduck Mail（暂定名）

Poolduck Mail 是面向企业客户的 Web SaaS。用户使用扫码枪提交条码或二维码后，系统会在当前租户和 location 范围内识别目标人员，创建邮件任务并记录处理结果。

## 产品目标

- 用统一系统承载扫码、人员邮箱匹配和邮件通知流程。
- 在多租户环境中保证数据隔离、角色权限和订阅门禁。
- 让扫码记录、邮件任务和异常结果可追踪。
- 以最小可用产品验证企业扫码通知业务闭环。

## 核心流程

1. 用户使用 `tenant_code + 用户名/邮箱 + password` 登录；operator 使用用户名或可选邮箱，
   tenant_manager 使用邮箱。
2. 用户选择当前办公室、学校或校舍（统一抽象为 `location`）。
3. 扫码枪提交该人员的进入码或离开码。
4. 系统在当前 tenant 和已授权的 location 内查找启用的人员邮箱映射。找不到映射时，工作台提示错误，系统不创建扫码记录或邮件任务。
5. 匹配成功后，系统记录动作并创建邮件任务。在 10 秒等待期内，当前地点的授权用户可以取消。到期后，系统重新检查订阅和资源状态，再处理发送。
6. 工作台显示处理结果，可按地点、状态和日期查看扫码历史。默认使用 mock provider 验证流程。

## MVP 产品能力

- 租户账号登录与基础角色控制（`tenant_manager` / `operator`）
- `tenant_manager` 管理本租户 `operator` 账号生命周期
- 订阅状态检查与功能门禁
- location 与人员邮箱映射查询
- 成功扫码记录与未映射输入提示
- 按进入或离开动作生成固定日文主题与正文，通知时间使用日本时间
- 邮件任务到期后自动处理，可重试的临时失败按退避策略重试
- 独立的平台管理控制台，支持人工开通租户、调整订阅与地点额度、查询平台操作审计
- 基础扫码工作台和操作记录

## 当前产品状态

MVP 核心业务链路已完成本地和 Staging 冒烟验证；当前实现还包含自动邮件任务处理、地点/人员停用与
14 天可恢复删除、operator 地点权限、租户内审计与历史导出，以及 HttpOnly Cookie 会话。
OCI Email Delivery 已在 Staging 完成一次受控单封验证，随后恢复 mock。生产发信、备份恢复、监控与正式对外发布仍需独立验收。

## MVP 边界

- 不支持桌面客户端或离线模式。
- 不支持前端自定义邮件正文。
- 不接入真实客户邮件凭据或生产数据。
- 不包含复杂工作流、全量 BI、多区域容灾或企业级合规认证实施。
